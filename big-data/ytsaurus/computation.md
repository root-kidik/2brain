# Вычисления: операции и scheduler

Как в YTsaurus выполняется батчевая обработка данных: какие бывают операции, как они превращаются в jobs и как scheduler распределяет их по кластеру. Базовые термины Chunk/Node/Table — см. [architecture.md](architecture.md).

## Термины

- **Operation** — распределённая вычислительная задача над одной или несколькими таблицами (например, Map, Reduce, Sort). Клиент запускает операцию, YTsaurus разбивает её на множество параллельных jobs.
- **Job** — минимальная единица выполнения операции: процесс, обрабатывающий часть входных данных (обычно один или несколько chunk'ов) на конкретном exec node.
- **Scheduler** — компонент кластера, распределяющий jobs операций по exec node'ам с учётом доступных ресурсов (CPU, память) и, где возможно, размещающий job рядом с нужными данными (data locality — см. [architecture.md](architecture.md)).
- **Pool** — единица планирования в scheduler: пользователи или команды объединяются в pools с гарантированной долей ресурсов кластера (fair-share scheduling); pools образуют дерево (pool tree) с наследованием квот.
- **Map** — операция, применяющая пользовательскую функцию к каждой строке входной таблицы независимо, без сортировки и группировки.
- **Sort** — операция, физически переупорядочивающая строки таблицы по заданным ключевым колонкам между chunk'ами.
- **Reduce** — операция, применяющая функцию к группам строк с одинаковым ключом; требует, чтобы вход был отсортирован по этому ключу (обычно результат предшествующего Sort).
- **MapReduce** — совмещённая операция: map-фаза, промежуточная сортировка и reduce-фаза выполняются в одном запуске, без материализации промежуточной отсортированной таблицы на диск между этапами.

## Как это работает

1. Клиент запускает операцию (например Map) над входной таблицей, указывая исполняемый код job'а.
2. Scheduler смотрит, из скольких chunk'ов состоит входная таблица, и создаёт по job'у на chunk (или группу chunk'ов) — этим определяется параллелизм операции.
3. Scheduler размещает jobs на exec node'ах, предпочитая узлы, где нужные chunk'и уже лежат локально (совпадение с data node), и учитывая fair-share квоту pool'а, к которому принадлежит операция.
4. Каждый job читает свою часть данных, выполняет пользовательский код и пишет результат в chunk'и выходной таблицы.
5. После завершения всех jobs операция считается завершённой, выходная таблица становится доступна для чтения.

### Планирование MapReduce-операции по pool'ам

```
                         Scheduler (pool tree)
                    ┌───────────────┴───────────────┐
                Pool "team-a" (40%)             Pool "team-b" (60%)
                    │                                 │
             Operation: MapReduce                Operation: Sort
                    │
        ┌───────────┼───────────┐
     Job (map)   Job (map)   Job (map)      ← читают chunk'и входной таблицы
        │           │           │              локально с data node, где они лежат
        ▼           ▼           ▼
   ┌─────────┐ ┌─────────┐ ┌─────────┐
   │ Exec    │ │ Exec    │ │ Exec    │
   │ node 1  │ │ node 2  │ │ node 3  │
   └─────────┘ └─────────┘ └─────────┘
        │           │           │
        └─────► промежуточная сортировка по ключу ◄─────┘
                        │
                 Job (reduce) → выходная таблица
```

Pool'ы "team-a" и "team-b" получают гарантированную долю ресурсов кластера (40%/60%). Если team-b не использует свою долю, scheduler временно отдаёт освободившиеся ресурсы team-a, но при конкуренции урезает обратно до квоты — в этом суть fair-share scheduling.

## Примеры использования

```bash
# Map: применить скрипт к каждой строке независимо
yt map "python3 process.py" \
  --src //home/project/orders \
  --dst //home/project/orders_processed

# Sort по ключу перед Reduce
yt sort --src //home/project/orders_processed \
  --dst //home/project/orders_sorted \
  --sort-by "user_id"

# MapReduce: map + группировка по ключу + reduce за один запуск
yt map-reduce \
  --mapper "python3 mapper.py" \
  --reducer "python3 reducer.py" \
  --map-output-table //tmp/intermediate \
  --reduce-by "user_id" \
  --src //home/project/orders \
  --dst //home/project/orders_by_user
```
