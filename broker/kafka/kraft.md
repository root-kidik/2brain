# KRaft и метаданные кластера

Кто и как хранит метаданные кластера (список топиков, партиций, их leader'ов) и проводит лидер-выборы при падении брокера.

## Термины

- **ZooKeeper** — внешняя система координации, которую Kafka исторически использовала для хранения метаданных кластера и проведения лидер-выборов. Отдельный сервис, требующий своего кластера и эксплуатации.
- **KRaft (Kafka Raft)** — режим работы Kafka без ZooKeeper. Метаданные кластера хранятся в самом Kafka, в специальном internal-топике, через Raft-консенсус между узлами.
- **Controller** — роль брокера в режиме KRaft: управляет метаданными кластера и лидер-выборами партиций. Может быть отдельным набором узлов (`process.roles=controller`) или совмещаться с ролью обычного брокера (`process.roles=broker,controller`) на небольших кластерах.
- **Raft** — алгоритм консенсуса, которым узлы-controller'ы договариваются о едином состоянии метаданных (кто leader какой партиции, какие топики существуют и т.д.), даже если часть узлов недоступна.

## Как это работает

- До Kafka 3.5: метаданные и лидер-выборы — в ZooKeeper, Kafka-брокеры сверяются с ним. Два кластера в эксплуатации (Kafka + ZooKeeper), два набора настроек, два места, где может что-то сломаться.
- Начиная с Kafka 3.5+ (production-ready): режим **KRaft** — рекомендованный, ZooKeeper deprecated и удалён в Kafka 4.0. Метаданные хранятся в самом Kafka-кластере, controller'ы реплицируют состояние через Raft — один кластер вместо двух, проще эксплуатация и быстрее восстановление после падения узла (не нужно ждать отдельный ZooKeeper-кворум).

```
ZooKeeper-режим (legacy):

 ┌───────────┐   метаданные,
 │ ZooKeeper │◄── лидер-выборы
 │  cluster  │
 └───────────┘
       ▲
       │
 ┌───────────┐
 │   Kafka    │
 │  brokers   │
 └───────────┘

KRaft-режим (current) — один кластер вместо двух:

 ┌──────────────────────────┐
 │  Kafka cluster            │
 │  ┌───────────┐            │
 │  │controller │ метаданные, │
 │  │  (Raft)   │ лидер-выборы│
 │  └───────────┘            │
 │        ▲                  │
 │  ┌───────────┐            │
 │  │  brokers   │            │
 │  └───────────┘            │
 └──────────────────────────┘
```

## Примеры использования

Инициализация нового кластера в режиме KRaft (без ZooKeeper):

```bash
# сгенерировать уникальный cluster ID
KAFKA_CLUSTER_ID=$(kafka-storage.sh random-uuid)

# отформатировать хранилище узла под этот cluster ID перед первым запуском
kafka-storage.sh format -t $KAFKA_CLUSTER_ID -c config/kraft/server.properties

# запустить брокер (роль broker+controller задаётся в server.properties: process.roles=broker,controller)
kafka-server-start.sh config/kraft/server.properties
```
